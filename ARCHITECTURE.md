# ARCHITECTURE.md — picomatch v4.0.5 reverse engineering

Scope: this document describes the original repository **as it is**, with `file:Lstart-Lend` citations into `lib/`, so that spec/build/review loops can re-read the original implementation on demand. No implementation suggestions, no port code.

---

## 1. Repository overview

### Purpose

picomatch is a zero-dependency JavaScript **glob-pattern → regex compiler and matcher**. It converts Bash/minimatch-style glob syntax (stars, globstars, question marks, braces, extglobs, POSIX bracket classes, negation) into a JavaScript `RegExp` **source string**, then delegates actual matching to the host JS regex engine. Matching semantics are therefore, by construction, ECMAScript regex semantics.

- Version: 4.0.5 ([package.json](package.json)), 2,444 source lines across 7 files.
- Zero runtime dependencies; `sideEffects: false`; published `files` = `index.js`, `posix.js`, `lib/`.
- Node >= 12, CommonJS only, ES2018 syntax ceiling (`.eslintrc.json` `parserOptions.ecmaVersion: 2018`).

### High-level architecture

Two phases, cleanly separated:

```
COMPILE (per pattern)                      MATCH (per input string)
pattern ──► regex source string    ──►     JS RegExp.exec / RegExp.test
(string in, string out)                    (string in, boolean + capture info out)
```

The compile phase is a three-stage pipeline (details in §6):

```
scan (optional, public)     parse (patterns → token list + output string)     compileRe/toRegex (string → RegExp)
lib/scan.js                 lib/parse.js                                      lib/picomatch.js
```

There is **no result cache** anywhere in `lib/` (verified by search: no `cache`/`memo` in `lib/*.js`). Users cache the returned matcher *functions* themselves. The performance story is fastpath templates (parse.js:L1330-L1414, L606-L655) that skip the full tokenizer for common patterns.

## 2. Source code architecture

### `lib/constants.js` — data, no logic

- `POSIX_CHARS` / `WINDOWS_CHARS` (constants.js:L12-L67): the regex **fragment dictionary**. Everything the parser emits for `*`, `?`, dot-lookaheads, slash literals, and anchors is a concatenation of these strings (`STAR`, `QMARK`, `NO_DOT`, `NO_DOTS_SLASH`, `ONE_CHAR`, `START_ANCHOR`/`END_ANCHOR`, `SEP`, …). Windows variants swap `[^/]` for `[^\\/]` and `/` for `[\\/]`.
- `POSIX_REGEX_SOURCE` (constants.js:L73-L89): `[[:alpha:]]`-style class → character-range source map (`__proto__` nulled).
- `REPLACEMENTS` (constants.js:L105-L110): exact-key map `{'***':'*', '**/**':'**', '**/**/**':'**'}` applied verbatim at the top of both `parse` and `parse.fastpaths` (parse.js:L361, L1338).
- Char-code constants `CHAR_*` (constants.js:L112-L161) consumed by scan.js via `charCodeAt`.
- Two factories: `extglobChars(chars)` (constants.js:L167-L175) builds per-platform extglob open/close fragments (`!(...)` close embeds `${chars.STAR}`); `globChars(win32)` (constants.js:L181-L183) selects the fragment table by `win32 === true`.
- Guardrails: `MAX_LENGTH = 1024*64` (constants.js:L93), `DEFAULT_MAX_EXTGLOB_RECURSION = 0` (constants.js:L6).

### `lib/utils.js` — helpers

| Export | Behavior | Cite |
|---|---|---|
| `isObject` | non-null, non-array object | utils.js:L11 |
| `hasRegexChars` / `isRegexChar` / `escapeRegex` | special-char detection/escaping via constants regexes | utils.js:L12-L14 |
| `toPosixSlashes` | `\` → `/` except before glob special chars | utils.js:L15 |
| `isWindows` | `navigator.platform` then `process.platform === 'win32'` | utils.js:L17-L28 |
| `removeBackslashes` | de-escape respecting bracket expressions | utils.js:L30-L34 |
| `escapeLast` | insert `\` before the **last unescaped** occurrence of `char` (recursive) — used for unbalanced `[ ( {` recovery | utils.js:L36-L41 |
| `removePrefix` | strips a leading `./`, records `state.prefix = './'` | utils.js:L43-L50 |
| `wrapOutput` | wraps `state.output` as `^(?:out)$` (or bare when `contains`), and when `state.negated` as `(?:^(?!out).*$)` | utils.js:L52-L61 |
| `basename` | last path segment; windows variant splits on `[\\/]`; empty trailing segment (trailing slash) selects the segment before it | utils.js:L63-L72 |

### `lib/scan.js` — pattern classifier (public, standalone)

Single-pass `charCodeAt` loop (scan.js:L84-L286) that classifies the pattern, tracking brace nesting (scan.js:L98-L154), brackets (L227-L248), extglob opener detection `X(` (L171-L204), globstar (L206-L215), leading `!` negation (L250-L254, `index === start`, honors `nonegate`). It **stops early** at the first glob indicator unless `parts === true || scanToEnd === true` (L53).

After the loop it computes the `base`/`glob` split from `start`, `lastIndex` and trailing-slash trimming (L293-L317), optionally unescapes (L319-L325), and assembles the state object (L327-L340). With `tokens`/`parts` options it post-processes slash positions into `tokens` (with `depth: 1` vs `Infinity` for globstars, L26-L30) and `parts` (L342-L386).

Not used by `parse`/`picomatch` internally — it is a pure public API (its only consumer in the pipeline is end users, e.g. `glob-parent`-style tooling).

### `lib/parse.js` — the compiler core

Four blocks:

1. **ReDoS-analysis helpers** (parse.js:L48-L347): `splitTopLevel`, `isPlainBranch`, `normalizeSimpleBranch`, `hasRepeatedCharPrefixOverlap`, `parseRepeatedExtglob`, `getStarExtglobSequenceChars`, `repeatedExtglobRecursion`, `analyzeRepeatedExtglob` — decide whether a `+(...)`/`*(...)` extglob risks catastrophic backtracking, and whether all branches collapse to single chars so a flat safe character class can be emitted instead.
2. **`expandRange`** (parse.js:L22-L38): brace ranges — calls `options.expandRange` if a function, else **lexicographic default `args.sort()`** (JS string sort) into `[a-z]`, probing validity with `new RegExp` in try/catch and falling back to escaped literal `a..z` on invalid ranges.
3. **`parse(input, options)`** (parse.js:L356-L1322): the tokenizer. Owns the parse-local structures (`tokens`, `extglobs`, `braces`, `stack`, `prev`), builds `state.output` incrementally as tokens are pushed, rewrites previous tokens in place when context disambiguates (globstar logic), sets `state.backtrack = true` on edits that invalidate the incremental string, and at the end optionally rebuilds output from the token list (L1308-L1319). Contains the **inline fastpath** at L606-L655 (skipped when pattern matches `/ ( ^[*!] | [/()[\]{}"] ) /`). May **recurse into itself** for a negate-extglob suffix like `!(*.d).ts` (L582-L591, with `fastpaths:false`).
4. **`parse.fastpaths(input, options)`** (parse.js:L1330-L1414): closed-form regex sources for `*`, `.*`, `*.*`, `*/*`, `**`, `**/*`, `**/*.*`, `**/.*`, plus `<fastpath>.<word>` chains via the `/^(.*?)\.(\w+)$/` fallback (L1394-L1402). Returns `undefined` on miss so the caller falls through to full parse.

### `lib/picomatch.js` — API and orchestration

- `picomatch(glob, options, returnState)` (picomatch.js:L43-L109): array fan-out (L44-L54), state-object passthrough detection (`glob.tokens && glob.input`, L56), `compileRe` vs `makeRe` selection (L63-L66), detached `regex.state` (L68-L69), recursive `ignore` matcher with hooks nulled (L71-L75), the returned `matcher` closure (L77-L102) with `onResult`/`onIgnore`/`onMatch` hooks, optional `matcher.state`.
- `picomatch.test` (L128-L156): input validation, empty-input short-circuit, `format` defaulting, **literal-equality shortcut** `input === glob` before regex, `matchBase`/`basename` branch, `regex.exec`.
- `picomatch.matchBase` (L172-L175), `picomatch.isMatch` (L194), `picomatch.parse` (L210-L213 — forces `fastpaths:false`), `picomatch.scan` (L242).
- `picomatch.compileRe` (L264-L284): anchors `^(?:out)$` unless `contains`, **second negation wrapper** `^(?!src).*$` for `state.negated`, `returnOutput` returns the raw string.
- `picomatch.makeRe` (L305-L321): tries `parse.fastpaths` when the pattern starts with `.` or `*` (L312), else full `parse`, then `compileRe`.
- `picomatch.toRegex` (L340-L348): `new RegExp(source, flags)`, swallows construction errors into `/$^/` **unless `debug === true`**.

### Entry points

- **Runtime entry:** `index.js` (only mutation: `options.windows` defaulting, and only if `options` is an object — see §8, issue #133).
- **Secondary entry:** `posix.js`.
- **Internal entry into compilation:** `picomatch.makeRe` → `parse`/`parse.fastpaths` → `compileRe` → `toRegex`.

## 3. Data flow

Trace of `require('picomatch')('**/!(*-dbg).@(js)')` then `matcher('src/foo.js', true)`.

### Phase A — matcher creation (`picomatch(...)`)

1. `index.js:L6-L14` — wrapper. If an options object was passed, `windows` is defaulted (cloned, not mutated) from `navigator`/`process.platform`; if no options object was passed, `windows` stays unset and compilation uses POSIX tables regardless of OS.
2. `picomatch.js:L43-L66` — not an array; pattern validated non-empty string; `opts = options || {}`; `posix = opts.windows` (note: *posix* means "the `windows` flag value", an inverted name); `makeRe(glob, options, false, true)` called.
3. `picomatch.js:L305-L321` (`makeRe`) — the pattern starts with `*`, so `parse.fastpaths` **is tried** (L312); no closed-form template matches this shape (the `**` case requires the exact string `**`, and the `.(\w+)$` fallback can't match the trailing `)`), so it returns `undefined` and the full `parse(input, options)` runs.
4. `parse.js:L356-L430` — `REPLACEMENTS` exact-map lookup (miss); length guard vs `MAX_LENGTH`; `PLATFORM_CHARS = globChars(opts.windows)` and `EXTGLOB_CHARS` built; template closures `globstar(opts)`, `star`, `nodot` fixed for this options set; `state` initialized with `bos` token whose `output` is `opts.prepend || ''`; `./` prefix stripped via `utils.removePrefix`.
5. `parse.js:L661-L1284` — main tokenizing loop, one char per iteration:
   - `**` ⇒ star-then-globstar machinery (L1124-L1244): prior token rewritten to `type: 'globstar'`, `output = globstar(opts)` fragments spliced into `state.output` (with surrounding slash-token surgery, L1188-L1218).
   - `!(...)` ⇒ `extglobOpen('negate', ...)` (L523-L537): pushes modifier token (with `ONE_CHAR` output if at string start) and a `paren` token carrying the extglob `open` fragment; extglob frame pushed onto `extglobs` stack.
   - inner chars, `-`, `@(...)` similarly; `)` closes via `extglobClose` (L539-L600): runs `analyzeRepeatedExtglob` (ReDoS), computes the platform `close` fragment (negate close appends `extglobStar`, choosing `globstar` when inner contains `/`, L571-L580), handles the special trailing-suffix recursion for cases like `!(*.d).ts` (L582-L591), marks `state.negatedExtglob` when the extglob starts at BOS (L593-L595).
   - Plain text runs coalesced by `REGEX_NON_SPECIAL_CHARS` lookahead (L1114-L1118) and merged into the previous `text` token (L512-L516).
6. `parse.js:L1286-L1321` — post-loop: unbalanced brackets/parens/braces escaped via `utils.escapeLast` (or `SyntaxError` if `strictBrackets`); `maybe_slash` appended when ending on star/bracket (L1304-L1306); if `state.backtrack` was set anywhere (globstar rewrites, POSIX-class expansion, brace ranges, extglob-risky rewrites) `state.output` is **rebuilt from the token list** (L1308-L1319). Returns `state` (with `output`, `tokens`, `negated`, …).
7. `compileRe` (`picomatch.js:L264-L284`) — wraps `state.output`: `^(?:…)$` (`contains` drops anchors); since `state.negated !== true` here, no negation wrapper. `toRegex` constructs `new RegExp(source, '')` and attaches `.state`.
8. Back in `picomatch()`: `regex.state` detached into `state` (L68-L69); no `options.ignore` ⇒ `isIgnored = () => false`; `matcher` closure returned; `matcher.state = state` because `returnState` was true (L104-L106).

### Phase B — matching (`matcher(input, true)`)

1. `picomatch.js:L77-L101` — calls `picomatch.test(input, regex, options, { glob, posix })`.
2. `picomatch.js:L128-L156` — input must be a string (throws `TypeError` otherwise); `''` short-circuits `{isMatch:false, output:''}`; `format = opts.format || (posix ? utils.toPosixSlashes : null)`; literal shortcut `input === glob` tried first, then on formatted output; `capture` or `matchBase`/`basename` choose `regex.exec(output)` vs `matchBase(...)`. Result: `{ isMatch: Boolean(match), match, output }`.
3. Result assembled as `{ glob, state, regex, posix, input, output, match, isMatch }` (L79); `onResult` hook fires **unconditionally** (L81-L83); on non-match returns `false`/result; `isIgnored(input)` checked next (fires `onIgnore` and flips `isMatch` to false); on pass, `onMatch` fires and `true`/result returned.

### Other entry flows

- `pm.isMatch(str, patterns, opts)` = `pm(patterns, opts)(str)` — no state retention (picomatch.js:L194).
- Array patterns: one matcher per pattern, evaluated in order, **first truthy result object wins** (picomatch.js:L44-L54).
- `pm(stateObject, opts)`: skips parsing — `compileRe(glob, options)` re-compiles a previously parsed `parse()` state (picomatch.js:L56,L63-L66).
- `pm.parse(pattern, opts)`: exposes the compiler with `fastpaths:false` forced — its returned state can differ in shape from `makeRe`'s internal state when makeRe used `parse.fastpaths` (compare fastpath state's `{negated:false, fastpaths:true, output}` vs the full 17-field parse state).

Verified reference outputs (Node, posix):

```js
pm.scan('a/b/*.js')          // { prefix:'', input:'a/b/*.js', start:0, base:'a/b', glob:'*.js',
                             //   isBrace:false, isBracket:false, isGlob:true, isExtglob:false,
                             //   isGlobstar:false, negated:false, negatedExtglob:false }
pm.makeRe('*.js').source     // '^(?:(?!\\.)(?=.)[^/]*?\\.js\\/?)$'   (via parse.fastpaths template)
pm.makeRe('**/!(*-dbg).@(js)').source
                             // '^(?:(?:^|\\/|(?:(?:(?!(?:^|\\/)\\.).)*?)\\/)(?:(?!(?:[^/]*?-dbg)\\.(js))[^/]*?)\\.(js))$'
                             // (pattern starts '*' ⇒ parse.fastpaths tried first; `**` template requires the exact
                             //  string `**` and the `.(\w+)$` fallback has no word-suffix here ⇒ miss ⇒ full parse)
pm.makeRe('!a.js').source    // '^(?!^(?:a\\.js)$).*$'                (compileRe negation wrapper)
pm.makeRe('!(a|b)').source   // '^(?:(?=.)(?:(?!(?:a|b)$))[^/]*?)$'
pm.compileRe(pm.parse('a/b')).source // '^(?:a\\/b)$'
pm.toRegex(pm.parse('a/b').output).source // 'a\\/b'  (no anchors — see §8 #130)
pm.isMatch('a/b', '*', {})   // false   (single `*` never crosses `/`)
pm.isMatch('.a', '*')        // false   (leading dot suppressed by NO_DOT lookahead)
pm.matchBase('foo/bar.js', '*.js') // true
```

## 5. Public API

All exported through `index.js` / `posix.js` (= `lib/picomatch.js`). "Calls" lists the internal functions exercised.

### `picomatch(globs[, options][, returnState])` — the factory — picomatch.js:L43-L109

- **In:** `String | Array<String> | parse-state object` (`{tokens, input}`), options object, `returnState` boolean.
- **Out:** `matcher(input[, returnObject])` → `Boolean | result-object`; when `returnState`, `matcher.state` is the parse/fastpath state. Throws `TypeError` for `''` or non-string/non-state patterns.
- **Calls:** `picomatch()` recursively (arrays + `options.ignore`), `picomatch.makeRe` (string input) or `picomatch.compileRe` (state input), `picomatch.test`, `utils.toPosixSlashes` (via test's format), `picomatch.matchBase` (via test), user hooks `onResult/onMatch/onIgnore`.

### `picomatch.test(input, regex[, options][, {glob, posix}])` — picomatch.js:L128-L156

- **In:** string input, compiled `RegExp`, options, context. **Out:** `{ isMatch, match, output }` (`match` is the `RegExp.exec` array/boolean; `output` is the formatted input).
- **Calls:** `utils.toPosixSlashes` (format default), `picomatch.matchBase`, `regex.exec`. Non-string input throws; `''` input returns `{isMatch:false, output:''}` **without throwing**.

### `picomatch.matchBase(input, glob[, options][, posix])` — picomatch.js:L172-L175

- **In:** string, `RegExp | String` glob; `posix` defaults to `options.windows`. **Out:** boolean.
- **Calls:** `picomatch.makeRe` (if glob is a string), `utils.basename`, `RegExp.prototype.test`.

### `picomatch.isMatch(str, patterns[, options])` — picomatch.js:L194

- **In/Out:** string(s) in, boolean out. **Calls:** `picomatch()` + the returned matcher.

### `picomatch.parse(pattern[, options])` — picomatch.js:L210-L213

- **In:** `String | Array<String>`. **Out:** parse state (17 fields, see §7) or array of them. **Forces `fastpaths:false`.**
- **Calls:** `lib/parse.js` `parse()`.

### `picomatch.scan(input[, options])` — picomatch.js:L242

- **In:** pattern string; options `parts`, `tokens`, `scanToEnd`, `noext`, `nonegate`, `noparen`, `unescape`.
- **Out:** scan state (12 base fields + optional `tokens`/`parts`/`slashes`/`maxDepth`, see §7).
- **Calls:** `lib/scan.js` `scan()`.

### `picomatch.compileRe(state[, options][, returnOutput][, returnState])` — picomatch.js:L264-L284

- **In:** parse-state with `.output`; **Out:** `RegExp` (or the raw output string when `returnOutput`), `.state` attached when `returnState`.
- **Calls:** `picomatch.toRegex`. Anchor wrapper `^(?:…)$` / negation wrapper `^(?!…).*$` live **here**, not in parse.

### `picomatch.makeRe(input[, options][, returnOutput][, returnState])` — picomatch.js:L305-L321

- **In:** non-empty string. **Out:** as `compileRe`. Throws `TypeError` on empty/non-string.
- **Calls:** `parse.fastpaths` (only if first char is `.` or `*` and `fastpaths !== false`), else `parse()`, then `compileRe`.

### `picomatch.toRegex(source[, options])` — picomatch.js:L340-L348

- **In:** regex source string. **Out:** `RegExp`; flags = `options.flags || (nocase ? 'i' : '')`; **construction errors are swallowed into `/$^/` (never-match) unless `options.debug === true`.**

### `picomatch.constants` — picomatch.js:L355

Re-export of `lib/constants.js`.

## 6. Internal pipeline — compile-time stages in order

Stages executed per pattern inside `makeRe` (parse.js:L356-L1322 unless noted):

0. **Pre-normalization** — exact `REPLACEMENTS` map (`***`→`*`, `**/**`→`**`, `**/**/**`→`**`), `maxLength` guard (throws `SyntaxError`), fragment-table selection (`globChars(opts.windows)`), local template closures computed once (`star`, `globstar(opts)`, `nodot`, `qmarkNoDot`, `capture`), minimatch alias `noext → noextglob`, `./` prefix strip (utils.removePrefix; a mid-loop equivalent for `./` after a `dot` token at parse.js:L975-L991).
1. **Fastpath selection** — three independent shortcut layers, each must be byte-identical to the slow path's output:
   - `parse.fastpaths` (picomatch.js:L312-L314 / parse.js:L1330-L1414) — only when pattern starts `.` or `*`; closed-form templates; miss ⇒ full parse.
   - Inline fastpath (parse.js:L606-L655) — full-parse entry but pattern free of `/ ( ) [ ] { } "` and not starting `*`/`!`; a single replace pass with `REGEX_SPECIAL_CHARS_BACKREF`, then `utils.wrapOutput` and early return.
   - If neither applies, the main loop runs.
2. **Main tokenizing loop** (parse.js:L661-L1284) — one char per iteration, dispatched in this fixed order: NUL skip → escape handling incl. run-length collapsing of `\\\…` and bash/non-bash `\/` (L672-L711) → in-bracket accumulation with POSIX-class expansion (`[[:alpha:]]` → range, L718-L758) → in-quote escaping (L765-L770) → quotes (L776-L782) → `(` (L788-L792) → `)` incl. extglob close dispatch (L794-L808) → `[` (L814-L827) → `]` incl. `literalBrackets` three-way (L829-L875) → `{` (L881-L895) → `}` incl. range assembly via `expandRange` and no-comma literal fallback (L897-L940) → `|` (L946-L952) → `,` inside braces → `|` (L958-L969) → `/` (L975-L991) → `.` incl. brace-range `dots` tokens (L997-L1015) → `?` incl. qmark-extglob and regex-group disambiguation after `(` (L1021-L1047) → `!` incl. negate-extglob and leading-BOS `negate()` (L1053-L1065; negate counts consecutive `!` parity, L457-L473) → `+` (L1071-L1089) → `@` (L1095-L1103) → plain text coalescing (L1109-L1122) → `*`/globstar state machine (L1124-L1284).
3. **Recovery loops** — unbalanced `[`, `(`, `{` closed by `utils.escapeLast` into the output (strictBrackets throws instead) (L1286-L1302).
4. **Trailing slash affix** — `maybe_slash` (`SLASH_LITERAL?`) appended when the last token is star/bracket and `strictSlashes !== true` (L1304-L1306).
5. **Backtrack rebuild** — if any stage set `state.backtrack`, rebuild `state.output` by concatenating token `output ?? value` (+ token `suffix`) (L1308-L1319).
6. **Anchor/negation wrap** — in `compileRe`: `^(?:output)$` or bare when `contains`; `state.negated` ⇒ `^(?!wrapped).*$` (picomatch.js:L270-L276). (The *inline* fastpath wraps via `utils.wrapOutput` instead — a different negation shape, `(?:^(?!wrapped).*$)`, utils.js:L52-L61.)
7. **RegExp construction** — `toRegex` with flags resolution and `/$^/` error fallback (picomatch.js:L340-L348).

The match-time pipeline is §3 Phase B (four steps).

## 7. Important data structures

### a) Regex fragment tables (static)

`POSIX_CHARS` / `WINDOWS_CHARS` (constants.js:L12-L67) and `EXTGLOB_CHARS(chars)` (constants.js:L167-L175). All parser output is built from these string constants (plus `POSIX_REGEX_SOURCE` ranges). Windows tables differ in: `SLASH_LITERAL`, `QMARK`, `STAR`, `DOTS_SLASH`, `NO_DOTS`, `NO_DOT_SLASH`, `NO_DOTS_SLASH`, `QMARK_NO_DOT`, `START_ANCHOR`, `END_ANCHOR`, `SEP`.

### b) `scan()` state object (scan.js:L327-L340)

```
{ prefix, input, start, base, glob,
  isBrace, isBracket, isGlob, isExtglob, isGlobstar,
  negated, negatedExtglob }
  + tokens, maxDepth           (opts.tokens)
  + slashes, parts             (opts.parts | opts.tokens)
```

Token entries: `{ value, depth, isGlob, …flags }`; `depth` = `Infinity` for globstar else `1` (`isPrefix` tokens keep `0`; scan.js:L26-L30).

### c) `parse()` state object (parse.js:L412-L428)

```
{ input, index, start, dot, consumed, output, prefix,
  backtrack, negated, brackets, braces, parens, quotes,
  globstar, tokens }          (+ peek, advance fns attached L444-L445;
                               negatedExtglob set later L594)
```

Fastpath replacement state is a **different, smaller** shape: `{ negated:false, fastpaths:true, output }` (picomatch.js:L310-L314; verified empirically).

### d) Token objects (parse.js)

Generic: `{ type, value, output?, prev }` — doubly-linked via `prev`; `output` defaults to `value` in `append` (L452-L455). Per-type extra fields:

- extglob open: `{ conditions, inner, parens, output (snapshot of state.output!), startIndex, tokensIndex }` (L523-L531); `inner` accumulates raw text via `push` (L507-L509); `conditions` incremented per `|` (L946-L949).
- brace open: `{ outputIndex, tokensIndex, dots?, comma? }` (L884-L890,L963,L1004).
- bracket: only `posix?` is set during accumulation (L722). There is **no** negation field on bracket tokens — under `posix !== true` a leading `!` inside `[…]` is appended literally (parse.js:L755), so `[!abc]` matches a literal `!`; the `!`→`^` rewrite happens only when `opts.posix === true` (L751-L753). This literal treatment is upstream issue #187.
- star/globstar: `star: true` flag path (L1128-L1136); `suffix` honored only during backtrack rebuild (L1315-L1317).

### e) Parser-mutable context (function-local)

`tokens` (array + `bos` head seeded with `opts.prepend`), `extglobs` (frame stack), `braces` (frame stack), `stack` (raw type-name stack for `braces`/`brackets`/`parens` balance, used by comma handling L962), `prev` (last token pointer).

### f) Match result object (picomatch.js:L79)

```
{ glob, state, regex, posix, input, output, match, isMatch }
```

`match` is the raw `RegExp.exec` array (so capture groups surface when `options.capture`), `output` the formatted input string; `isMatch` may be flipped false by the `ignore` check after `onResult` already fired.

## 8. Potential high-risk modules

Ranked by expected parity risk for a faithful reimplementation. Upstream issue numbers are the known-buggy behaviors the test suite may encode; per the project rulebook these must be **preserved, not fixed**.

1. **`parse.js` star/globstar state machine (L1124-L1284) and `push()`'s globstar demotion (L493-L505).** Position-sensitive token rewriting: six context branches keyed on `prev`/`prev.prev` token types (bos/slash/star), `eos`, and `rest[0]`; in-place edits to `state.output` with negative-index slicing; `/^\([^?]/`-based extglob opener probe; collapsing of consecutive `/**/` (L1168-L1176); `bash` mode forks (L1156, L1248-L1255); `state.backtrack` invalidation. Densest bug surface in the codebase; known upstream issue area #142/#104 (`**` inside parens).
2. **Extglob close + ReDoS analysis (parse.js:L164-L347, L523-L600).** `analyzeRepeatedExtglob` decides three ways — safe, risky→literalize, risky→emit combined char class (`safeOutput`, L340-L344) — driven by `maxExtglobRecursion` coercion (`false` vs number vs default 0, L288-L295). Risky handling **rewrites already-emitted tokens in place** (L548-L560) and sets `state.backtrack`. Negate-close has three sub-branches (`inner` with `/`, `eos`, `/^\)+$/` remainder, magic suffix recursion L582-L591 with forced `fastpaths:false`). This is the area of the acknowledged-incomplete ReDoS fix (upstream #175); `test/malicious.js` is the adversarial corpus.
3. **Negation, in three places with two wrapper shapes.** `negate()` parity counting of leading `!` runs with the `(peek(2) !== '(' || peek(3) === '?')` extglob guard (parse.js:L457-L473); `state.negatedExtglob` (L593-L595); and the two **different** output wrappers — utils.wrapOutput `(?:^(?!out).*$)` (utils.js:L57-L59, inline fastpath) vs compileRe `^(?!(?:out-anchor-wrapped)).*$` (picomatch.js:L274-L276). Upstream #148 (negation not inverting).
4. **POSIX classes and bracket negation (parse.js:L718-L758).** Class expansion active under `posix !== false` while `!`→`^` rewriting requires `posix === true` — the asymmetric coercion encodes upstream #187 (POSIX bracket negation inverted). Plus `^`-first bracket `/`-injection for `[^…]` without slash (L846-L849) and the `literalBrackets` three-way on `]` (L854-L874: regex chars vs explicit-true vs unset-both-match alternation).
5. **Brace ranges via `expandRange` (parse.js:L22-L38, L905-L923).** Default JS `args.sort()` is **lexicographic string sort** (no comparator) before forming `[a-z]`; validity probed by constructing a real `RegExp` in try/catch; invalid ranges fall back to dot-joined escaped literals (`a..z`). Token-list surgery pops and reassembles `dots` runs (L908-L919). Off-by-one or sort-order divergence here silently breaks `test/braces.js`.
6. **The three fastpath layers and their byte-identity obligation (picomatch.js:L310-L318, parse.js:L606-L655, L1330-L1414).** Template outputs must equal the slow path character-for-character across the full option matrix (`dot`, `bash`, `capture`, `strictSlashes`, `windows`, `noglobstar`), and fastpath produces a differently-shaped state object than full parse (§7c) — visible to `returnState` users and to the structural oracle.
7. **`compileRe` / `toRegex` boundary (picomatch.js:L264-L348).** Anchors and negation wrapping live outside parse (so `pm.parse()` output is unanchored — upstream #130); `contains` removes anchors; `toRegex` swallows construction errors into `/$^/` unless `debug === true` — the library's "never throws for a compiled glob" contract (contrast: `makeRe`/`parse` **do** throw `TypeError`/`SyntaxError` for type/length violations).
8. **`picomatch.test`'s non-regex shortcuts (picomatch.js:L128-L156).** Literal string equality `input === glob` is tried **before** the regex (result differs when `options.capture` forces exec anyway, L147); `format` default uses `toPosixSlashes` only when `posix` (i.e. the `windows` option) is truthy; empty input returns false without touching the regex; `basename` fallback splits on the trailing segment with trailing-slash lookback (utils.js:L63-L72) — upstream #89 (matchBase vs docs).
9. **`scan.js` base/glob split arithmetic (scan.js:L293-L317) and token/part post-processing (L342-L386).** Index bookkeeping (`start`, `lastIndex`, `./` and `!` prefix shifting L297-L301, trailing separator trim L313-L317) drives the structural oracle output field-by-field; `opts.noext === true` post-blanks `isExtglob`/`isGlob` (L288-L291) after the loop already ran.
10. **Platform defaulting at the boundary (index.js:L6-L14).** `windows` is defaulted from `navigator/platform` **only when an options object is passed** — `pm('*')` and `pm('*', {})` compile with different platform tables on Windows. Upstream #133; also note the inverted local variable name `posix = opts.windows` (picomatch.js:L63).
11. **Alternation-order and regex-engine delegation.** Matching is ECMAScript-regex-order-sensitive (alternation is leftmost-first); the library's `#154` alternation-order behavior emerges from the emitted source and V8's engine, not from any picomatch code — equivalence requires reproducing emitted sources exactly, then executing under ECMAScript semantics. There's also the `throw` contrast: `parse` throws on non-string/over-long input and `strictBrackets` imbalance, while `toRegex` never throws without `debug`.

## 12. Behavioral oracle — what exactly is compared

The key structural fact: **picomatch's product is a regex source STRING**; matching is delegated to the JS RegExp engine (§1). So equivalence is checked top-down, strongest first:

1. **String identity (strongest).** `makeRe(pattern, opts).source` — original vs port must be **byte-identical strings** for the same (pattern, options) pair. Covers ~90% of the codebase deterministically, no sampling. The suite itself already exercises this: 19 `.source` assertions in options.maxExtglobRecursion.js, byte-exact `makeRe(...).toString()` in malicious.js:41, `/.test()` source templates in options.maxExtglobRecursion.js:147-151.
2. **Structural identity.** `scan(pattern, opts)` full 12-field state (api.scan.js deep-equals; parts/tokens variants) and `parse()` token streams + state booleans (`api.picomatch.js` `.parse > tokens`, `.state > negatedExtglob`). Serialize canonically, compare.
3. **Boolean identity.** `isMatch(str, pattern, opts)` — the ~1,950 boolean `it()`s. Necessary but weakest: a boolean match can hide a divergent source that fails on an untried input.

Rationale, verbatim from the rulebook: check oracle 1 FIRST; only if 1–3 all pass does performance matter. The execution engine below oracle 1 must implement ECMAScript regex semantics (lookarounds/backreferences are used directly in glob patterns — test/regex-features.js).

## 13. Invariants — the laws

1. **Fragment law.** Every emitted regex fragment comes from the constants tables (POSIX or Windows); fragments are concatenated, never re-derived ad hoc. Platform table is chosen ONCE at compile start (`globChars(opts.windows)`, parse.js:L377) and never mixed mid-pattern.
2. **Token-order law.** `state.output` is the concatenation of token `output ?? value` in token order; any rule that edits earlier tokens must set `state.backtrack` so output is rebuilt (parse.js:L1308-L1319). Token streams themselves are asserted (api.picomatch.js `.parse > tokens`).
3. **Escaping law.** Regex-special characters in literal text are escaped at emission time; quote-wrapped chars are escaped per-char (parse.js:L765-L770); backslash runs longer than 2 are collapsed (parse.js:L689-L699); unbalanced `[ ( {` are escaped at recovery via `utils.escapeLast`, never silently dropped (parse.js:L1286-L1302).
4. **Anchor law.** `parse()` output is never anchored; anchors (`^(?:…)$`) and the negation wrapper are added only by `compileRe` (picomatch.js:L270-L276) or `utils.wrapOutput` on the inline fastpath (utils.js:L52-L61) — two different negation shapes, both reproduced exactly.
5. **Dotfile law.** Leading dots are excluded by lookaheads (`NO_DOT`/`QMARK_NO_DOT`) unless `options.dot === true`; `*`/`?` at segment starts get the extra `(?=.)` guard (parse.js:L1277-L1280). `**` never matches `.` or `..` segments unless `dot`.
6. **Slash law on posix tables.** A single `*`/`?` never matches `/`; only `**` (globstar) crosses separators; `maybe_slash` is appended only when `strictSlashes !== true` (parse.js:L1304-L1306).
7. **Negation law.** Leading `!` runs collapse by parity (odd ⇒ negated) and never negate when followed by `(` extglob rules (parse.js:L457-L473); the wrapper is applied once at wrap time; `negatedExtglob` is a state flag, not an output change.
8. **Failure law.** `parse`/`makeRe` throw only for: non-string input (`TypeError`), over-`maxLength` input (`SyntaxError` with the exact `Input length: N, exceeds maximum allowed length: M` message — asserted byte-format in test/malicious.js:25-27), and `strictBrackets` imbalance. `toRegex` NEVER throws — invalid sources become `/$^/` unless `debug === true` (picomatch.js:L340-L348).
9. **No-mutation law.** Caller options objects are never mutated (cloned in index.js:L10, parse.js:L363, fastpaths L1331); no global/shared state anywhere — no caches (§1), every call is a pure function of (pattern, options).
10. **Bug-parity law.** Known-buggy behaviors from §8 (e.g. `[!abc]` literal treatment without `posix:true`, `windows` defaulting gated on an options object) are reproduced as-is; divergences are documented, not fixed.
